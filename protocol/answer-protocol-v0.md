# OpenCompass 回答与跃迁协议 v0

> 从属：`CONSTITUTION.md`（铁律 3）  
> 配套：`protocol/safety.md`、`ontology/education-map-v0.md`  
> 状态：生效（工程可执行规格）  
> 用途：约束所有「协议问答」输出的结构、定位与失败条件。浏览节点页时同一套区块可复用渲染。

---

## 1. 一句话

每次有效回答必须让用户**更会教自己，或更会教下一代**；六段可折叠，不可删除；LLM 只是表达层，不得输出无结构散文作为主路径成功结果。

---

## 2. 适用范围

| 适用 | 不适用 |
|------|--------|
| 用户提问 / 从节点「深挖」 | 纯静态节点阅读（仍建议同构展示双路径与练习） |
| 无命中节点时的枢纽降落回答 | 危机安全路径（见 `safety.md`，优先求助，可缩短协议） |
| 系统生成的路径推荐说明 | 无协议约束的自由闲聊（宪法禁止作为主路径） |

---

## 3. 定位（Locate）— 回答前必做

对齐教育地图 §9，最小逻辑：

1. **意图** `intent`：`self`（自我教育）| `next_gen`（代际）| `fact`（纯事实）| `crisis`（危机 → 走安全协议）  
2. **枢纽**：关键词 / 检索 → H1–H6  
3. **节点**：Top-k；无命中则挂最近枢纽导论（`H*._hub`，未建时用枢纽一句话 + 地图摘要）  
4. **路径角色**：按意图加权 `self_path` / `next_gen_path`  
5. **跃迁规划**：准备至少 1 条、目标 3 条——同枢纽深化、跨枢纽系统（macro/micro）、自我↔代际切换  

定位结果写入输出的 `locate` 字段，供 UI 展示「你落在地图的哪里」。

---

## 4. 六段区块（不可删除）

| 字段 | 中文名 | 要求 |
|------|--------|------|
| `direct` | 直答 | 可理解、可执行；先给结论与下一步，不绕弯 |
| `mechanism` | 机制 | 为何如此；给可迁移的底层理由，忌堆术语 |
| `era_shift` | 时代坐标 | AI 爆发后，本问题优先级或含义如何变了 |
| `bounds` | 边界与反例 | 何时不适用；常见误用 / 鸡汤 / 极端 |
| `jumps` | 跃迁 | 尚未被问到但值得问的下一问；须挂地图节点 ID |
| `practice` | 练习 | 一个 10–30 分钟内可完成的小动作（对自己或对下一代） |

**语气**：诚实优于讨好；多视角优于独断；不代用户做重大人生抉择（给框架与选项）。  
**铁律 1**：AI 是同学与工具；引导用户离开 AI 时仍能想清楚。  
**铁律 2**：重要回答尽量同时触及自我与代际（至少在 `jumps` 或 `practice` 一侧体现）。

## 5. 机器输出 schema（`AnswerPayload`）

工程强制：模型输出必须可解析为下列 JSON（字段名稳定）。解析失败 = 协议失败。

```ts
type AnswerPayload = {
  locate: {
    intent: 'self' | 'next_gen' | 'fact' | 'crisis'
    nodeIds: string[]
    hub?: 'H1' | 'H2' | 'H3' | 'H4' | 'H5' | 'H6'
  }
  direct: string
  mechanism: string
  era_shift: string
  bounds: string
  jumps: {
    id: string
    reason: string
    edgeType?: string
  }[]
  practice: string
}
```

### 校验规则

- `direct` / `mechanism` / `era_shift` / `bounds` / `practice`：非空字符串  
- `jumps.length` ≥ 1（目标 3）；`jumps[].id` 应为已知节点或显式 `planned:` 前缀  
- `intent === 'crisis'` 时改走 `safety.md`，本 schema 可降级为求助导向短答  
- 禁止用空字符串或占位符（如「略」「TODO」）凑字段  

### 失败与降级

1. **重试一次**结构化生成（同一 locate 上下文）  
2. 仍失败 → **降级**：用命中节点原文拼装六段（缺段则标明「待节点补全」），不得展示裸模型散文当作成功  
3. 无节点可拼 → 枢纽导论模板 + 指向路径 D / 地图首页  

---

## 6. 跃迁（Navigator）细则

每次成功回答结束时，优先推荐：

1. **同枢纽深化**（同 `hub` 的 `requires` / `enables` / `see_also`）  
2. **系统边**（`macro_of` 或 `micro_of`）  
3. **自我↔代际**（`teaches` 或反向切到 H6 / 从 H6 切出）  

文案用「值得接着问 / 接着走」的问题句，而非课程目录口吻。  
禁止无限相关刷屏：UI 默认展示不超过 3 条跃迁。

---

## 7. 与浏览的统一

节点页渲染建议映射：

| 节点字段 / 正文 | 协议区块 |
|-----------------|----------|
| summary + L0/L1 结论 | 直答 |
| L2 模型 | 机制 |
| `ai_era_shift` | 时代坐标 |
| `anti_patterns` | 边界与反例 |
| `edges` | 跃迁 |
| `practice` | 练习 |
| `self_path` / `next_gen_path` | 双路径（浏览增强，问答中按 intent 择一为主） |

消灭「百科一套话术、聊天另一套话术」的分叉。

---

## 8. 系统提示词要点（实现备忘）

编排器注入时至少包含：

1. 本协议摘要 + `AnswerPayload` 字段表  
2. 命中节点的 frontmatter 与分层摘要  
3. 可用边列表（供 `jumps`）  
4. 安全红线指针（`safety.md`）  
5. 明确指令：只输出 JSON；不闲聊；不代做人生决策  

---

## 9. 版本

- 协议变更须升版（v0.x）；与宪法冲突时先改宪法或改本协议，禁止静默架空。  
- 应用代码以本文件与 JSON schema 校验为准。
